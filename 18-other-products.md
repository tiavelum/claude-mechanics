# 18 Other products

Prefix: PRD · Scope: Claude products outside the Claude app and Claude Code (Claude Tag, Claude for Microsoft 365, Claude Design, Claude Science, Claude Security): what each is, where its sessions run, what it shares with the Claude app and Claude Code, its settings and organization controls, how its data is handled, and which plans have it · Last checked: 2026-10-08

## Claude Tag

- **PRD-001** `documented` Claude Tag puts Claude into an organization's Slack channels: anyone in a channel can tag `@Claude` into a thread and hand it a task, and Claude works under its own identity and posts its progress and result in the thread; it is in public beta. [tag] [tag-how]
- **PRD-002** `documented` Claude Tag is available on Team and Enterprise plans on Anthropic's own service, and not on Free, Pro or Max or through third-party deployments; Pro and Max users are pointed to Claude Code in Slack, which runs each session under an individual's account. [tag] [cc-tag]
- **PRD-003** `documented` Claude in Slack switched over to Claude Tag on 2026-08-03. [tag-help]
- **PRD-004** `documented` Claude Tag has three surfaces: tagging in a channel, direct messages and the AI assistant panel in Slack. [tag-help]
- **PRD-005** `documented` Each thread that needs work gets its own session in an ephemeral cloud sandbox, the infrastructure and engine of Claude Code on the web; a few minutes after a turn the sandbox is released and the next reply resumes the session in a fresh one, so the thread and its transcript persist while files that existed only in the sandbox do not. [tag-how] [tag-sec]
- **PRD-006** `documented` A channel used at its top level also has a session of its own, which Claude replaces after about an hour without activity, when the channel's configuration has changed, or once it is about a day old and the channel has gone quiet; two threads are separate sessions that share no state. [tag-how]
- **PRD-007** `documented` A thread keeps the skills, plugins and custom instructions it started with, while connectors and domain rules are enforced on each request, so a configuration change other than a connector reaches only threads started after it. [tag-how]
- **PRD-008** `documented` In a channel or group DM, Claude acts with service accounts and connectors that an admin applies to all of Slack, one workspace or one channel, and its pull requests come from the Claude GitHub App; in a one-to-one DM it runs on the member's own claude.ai account with that member's connectors, and its work is attributed to the member except for pull requests. [tag-how] [tag-sec]
- **PRD-009** `documented` Credentials for Claude Tag connectors are kept in a credential store outside the sandbox and added to requests at the network boundary by Agent Proxy; outbound traffic from a channel session is denied by default except to hosts that a credential's allowed websites, an allowed domain or the environment's network access level covers. [tag-sec]
- **PRD-010** `documented` A routine runs a Claude Tag session on a schedule, on a channel watch or on a repository event, with the same channel access as a typed request. [tag-how]
- **PRD-011** `documented` Claude Tag keeps memory per channel, workspace notes saved from public channels that every channel of the workspace reads, private channels only reading them, and separate notes per group DM and per one-to-one DM, the latter stored with the workspace rather than with the member's Claude account. [tag-mem]
- **PRD-012** `documented` Anyone in a channel can read, add to and correct its Claude Tag memory by asking Claude, and an Owner can view, edit or delete the memory files of a workspace and its channels; Claude can also list and read earlier sessions of the channel, but cannot search across them in full text. [tag-mem]
- **PRD-013** `documented` Claude Tag is separate from the Claude app: Slack conversations and Claude chat history do not appear in each other, Claude does not read a project's instructions or knowledge in Slack, and a channel cannot be pointed at a project. [tag-help] [tag-cust]
- **PRD-014** `documented` Custom instructions in Claude Tag are set per scope (the organization, a workspace or a channel), are read in every session there and outrank channel memory; channel members can set a channel's instructions from its Configure page unless an admin restricts editing. [tag-cust]
- **PRD-015** `documented` Claude Tag connectors, plugins and skills are configured per scope and are separate from the connectors, skills and MCP servers in a member's own claude.ai or Claude Desktop account; Claude uses a member's personal connectors in a channel only for that member's own tasks and after the member allows it. [tag-cust] [tag-sec]
- **PRD-016** `documented` When a session clones a repository granted to the channel, the repository's `CLAUDE.md`, `.claude/CLAUDE.md`, `.claude/rules/*.md` and `.claude/skills/` load and the hooks in `.claude/settings.json` run; `.mcp.json` is not loaded, and nothing from the user's machine, such as `~/.claude`, a personal `settings.json` or local MCP servers, reaches a session. [tag-cc]
- **PRD-017** `documented` Claude Tag sessions run in auto mode at the model's default effort, which cannot be changed; an admin pre-approves actions with auto mode allow rules, at most 50 per scope and 1,024 characters each, which carry down from the organization and workspace to the channels beneath. [tag-cc] [tag-cust]
- **PRD-018** `documented` The model of new sessions is set per scope and inherited from the parent scope where none is set, and members can switch a thread's model, or the channel default unless channel member edits are blocked; the permission checker of channel sessions runs on Sonnet 5 and the checks for tasks with personal connectors on Opus 5, so turning either model off on Enterprise blocks or declines that work. [tag-cust]
- **PRD-019** `documented` Claude Tag and Claude Code share one fast mode setting, which is off by default on Team and Enterprise, is turned on under Admin settings > Claude Code and draws from usage credits. [tag-cust]
- **PRD-020** `documented` Only a Primary Owner or Owner sets up Claude Tag, at `claude.ai/admin-settings/claude-tag`, by pairing the Slack workspace with a code; on Enterprise, the Claude Tag Admin permission delegates further administration. [tag-help] [tag] [tag-cust]
- **PRD-021** `documented` By default anyone in a paired Slack workspace can use Claude in channels without a Claude seat; an Owner can restrict it to members of the Claude organization on Team, or to roles with the Claude Tag in Slack capability on Enterprise, and the restriction covers DMs too. [tag] [tag-sec]
- **PRD-022** `documented` Claude Tag adds no per-seat charge: channel, thread and group DM work draws on a usage balance that an Owner funds, capped per billing period by a spend limit, while a one-to-one DM from a member with a connected Claude account follows that seat's usage limits. [tag]
- **PRD-023** `documented` Anthropic stores Claude Tag session transcripts, including earlier versions of edited messages and what Claude retrieved, as well as memory, routines, scopes, connectors, account links and published artifacts; deleting or editing a message in Slack does not remove it from a transcript. [tag-data]
- **PRD-024** `documented` During the beta, Claude Tag data has no automatic retention period and is kept until an action deletes it, such as disconnecting the workspace, uninstalling the app, deleting a Slack channel or removing a channel's scope; artifacts a session published follow the organization's retention for shared artifacts. [tag-data]
- **PRD-025** `documented` The help center says conversations are deleted from Claude within 30 days of disconnecting the integration or uninstalling the app. [tag-help]
- **PRD-026** `documented` Claude Tag is not available to organizations with Zero Data Retention, a customer-managed encryption policy, or the HIPAA configuration for Claude Code and Cowork in local mode, because it retains memory and transcripts; an organization that adopts such a setting after pairing keeps its stored data, but Claude stops responding. [tag-sec] [tag-data]
- **PRD-027** `documented` During the beta, Claude Tag transcripts and memory are not part of the organization's data exports and the Compliance API neither lists nor deletes Claude Tag sessions; disconnecting a workspace and removing a channel's scope are recorded in the audit log. [tag-data]
- **PRD-028** `documented` Admins have no page or export of the individual messages people send Claude Tag; an Owner's Activity page lists scheduled work, memory files and network events. [tag-how]
- **PRD-029** `documented` An artifact published from a Claude Tag session can be opened by anyone with access to the source channel, has no share setting, and is updated by asking Claude in the thread or by a comment on the page. [tag-sec]

## Claude for Microsoft 365

- **PRD-030** `documented` Claude for Microsoft 365 is a set of add-ins for Excel, PowerPoint, Word and Outlook in which Claude reads and edits the file or email that is open; every add-in runs in the browser view that Office provides and is served from `pivot.claude.ai`. [m365] [m365-store]
- **PRD-031** `documented` Claude for Excel is generally available on Pro, Max, Team and Enterprise, and Claude for Outlook is in beta on the same plans; use of an add-in is tied to the user's Claude account and draws on its usage limits. [m365-xl] [m365-ol]
- **PRD-032** `documented` A user installs an add-in from Microsoft AppSource and signs in with a Claude account; an organization deploys it through the Microsoft 365 Admin Center or a custom manifest, and Claude for Outlook also needs a one-time, tenant-wide Microsoft Graph consent from a Global Administrator or an Entra application of the organization's own. [m365-xl] [m365-ol]
- **PRD-033** `documented` An organization can run the add-ins without Claude accounts through Amazon Bedrock, Google Cloud Vertex AI, Azure AI Foundry or an LLM gateway, in which case the models come from that platform, working across apps is not supported, and connectors and skills may be missing. [m365-xl] [m365-across] [m365-cs]
- **PRD-034** `documented` Connectors enabled in the Claude settings are offered in every add-in under the + button, and a skill can be invoked directly by typing `/`, which lists only the skills relevant to the open app. [m365-cs]
- **PRD-035** `documented` Claude for Excel has an Instructions field in its settings that applies to every conversation in Excel and is separate from the instructions set in PowerPoint or Word. [m365-xl]
- **PRD-036** `documented` The add-ins share conversation state, so Claude can read from one open file or email and write to another; this needs "Let Claude work across files" in each add-in on each device, on by default on Pro and Max and off on Team and Enterprise, where an owner also controls "Let Claude work across apps" under Organization settings > Office agents. [m365-across]
- **PRD-037** `documented` Working across apps reaches only files and emails that are open: Claude cannot create, open, close or switch files from an add-in. [m365-across]
- **PRD-038** `documented` Chat history of the add-ins is kept only in the browser storage of the user's device, not on Anthropic's servers and not synced between devices; it is separate per user, organization and Office app, limited to the 50 most recent conversations of each, and on Office on the web may be evicted by the browser at any time. [m365-store]
- **PRD-039** `documented` The add-ins also keep uploaded skills, connector registrations and the sign-in credential, unencrypted, in the device's browser storage; uploaded skills and connector registrations belong to the storage rather than to a user, so people sharing an operating system account share them. [m365-store]
- **PRD-040** `documented` In Claude for Excel, long conversations are compacted into new conversations automatically, and the model list is a subset of the Claude models chosen for Office work, further limited by the organization's model access settings. [m365-xl]
- **PRD-041** `documented` Inputs and outputs of the add-ins are deleted from Anthropic's backend within 30 days, except in the cases of the privacy policy; the add-ins do not inherit an organization's custom retention settings and are not part of Enterprise audit logs or data exports. [m365-across] [m365-xl]
- **PRD-042** `conflicting` Whether add-in sessions reach the Compliance API: the Claude docs say that, for Enterprise organizations with the Compliance API enabled, Excel, Outlook and other add-in sessions are included, in public beta, while the help-center article on Claude for Outlook says Outlook is not included. [m365-across] [m365-ol] [m365-ol-help]
- **PRD-043** `documented` Enterprise organizations can send the add-ins' full audit telemetry, prompt content and tool inputs and outputs included, to an OpenTelemetry collector of their own, which Pro, Max and Team cannot; the telemetry sent to Anthropic is filtered to counts, durations and error categories. [m365-ent] [m365-store] [m365-ol]
- **PRD-044** `documented` Claude for Outlook reads the open item through Office.js and the wider mailbox and calendar through Microsoft Graph calls made in the browser, whose token is not sent to Anthropic; it does not request permission to send mail, so drafts and invites land unsent, and it learns the user's tone from the sent folder. [m365-ol]
- **PRD-045** `documented` For add-ins signed in with Claude accounts, the Enterprise Analytics API reports usage per user and per surface, and Team and Enterprise admins can export spend per seat and surface as CSV from the usage analytics dashboard. [m365-ent]

## Claude Design

- **PRD-046** `documented` Claude Design, a product of Anthropic Labs, makes designs, interactive prototypes, one-pagers and other visual work from a conversation, on a canvas beside the chat that the user refines by chat, inline comments or direct editing of elements. [design] [design-news]
- **PRD-047** `documented` Claude Design is reached from a conversation, with Output > Design in the message box, from a Design template in the Artifacts tab, and in the standalone experience at claude.ai/design, which keeps its existing projects; in the mobile apps a design can be requested and viewed full screen, while starting from a template, editing the canvas and sharing need the web or desktop. [design]
- **PRD-048** `documented` Standalone Claude Design has its own place in the sidebar of Claude Desktop and its own organization setting, "Enable for your organization" under Organization settings > Claude Design, separate from the Design template under Organization settings > Artifacts; turning on one does not turn on the other, and on Enterprise custom roles control access to the standalone one. [design-admin] [design-blog]
- **PRD-049** `documented` Claude Design projects use the organization's design system, imported from a GitHub repository, design files or uploads, or from a local codebase with `/design-sync` in Claude Code, and Claude checks its output against it before showing it; an organization can keep several design systems. [design] [design-admin]
- **PRD-050** `documented` Any member with access to Claude Design can create and edit design systems, while on Enterprise admins can reserve publishing, setting the default and deleting them to specific users; design systems made at claude.ai/design can move over for use in any chat, Claude Code included. [design] [design-admin]
- **PRD-051** `documented` A design starts private, and Share sets who can view, comment on or edit it; a project's preview runs in a sandboxed frame on a separate content domain of Anthropic, opened with short-lived signed tokens that are checked against the sharing permissions each time, so removing someone's access takes effect at once. [design] [design-admin]
- **PRD-052** `documented` Claude Design has no version history yet, saving a state of the project only when the user asks Claude to, and editing by several people at once is basic and may not work reliably. [design]
- **PRD-053** `documented` A design can be exported as a .zip, PDF, PPTX or standalone HTML, to Google Slides from claude.ai/design only, sent to partner tools, or handed to Claude Code on the user's machine or on the web. [design]
- **PRD-054** `documented` Claude Design draws on the same usage limits as the rest of Claude, Claude Code included, with no allowance of its own, and stops when they are reached unless usage credits are on. [design] [design-blog]
